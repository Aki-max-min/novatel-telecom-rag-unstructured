## Learning Objectives

Agents can check outage status tools, set correct customer expectations, and escalate P1 issues.

## Using the Outage Dashboard

Agents must check the internal NOC dashboard (not just the customer-facing map, which may lag by up to 15 minutes) before confirming outage status to a customer.

## Setting Expectations

Never commit to an exact restoration time unless it is published by NOC. Use ranges (e.g., 'within the next 4 hours') and offer SMS notification opt-in for restoration alerts.

## Escalation Trigger

Any report suggesting >500 affected customers in one area that is not yet on the dashboard should be flagged to NOC immediately as a potential undetected outage.

## Key Definitions

- **SLA** — the target time within which a request or issue should be resolved.
- **Escalation** — handing a case to a specialist team when first-line steps do not resolve it.

## Worked Example

During a routine interaction, the agent identifies this scenario, applies the documented process, and confirms with the customer before closing the case.

## Common Mistakes

- Skipping identity verification before making account changes.
- Closing a case before the customer confirms the issue is resolved.

## Escalation

- Unresolved cases are automatically flagged for supervisor review after the stated SLA window, ensuring no request is left without a defined next action.
